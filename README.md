# MAISON LISA

A private digital boutique for Lisa's artistic, non-explicit photography. It includes accounts with ID-based age verification, a private real-time chat with Lisa, personalised requests and offers, a multi-item shop with discounts, protected delivery of purchases, and a full creator dashboard. Every screen exists in eight languages.

> **Status: feature-complete in development mode. It is not production-ready yet.**
> Two parts run against **labelled simulators** in development: identity verification and payments. Their real adapters (Veriff and Verotel FlexPay) are implemented but have **not been tested against live accounts**. The legal texts and seller details are **placeholders** that need professional review. All imagery is **generated demo artwork** and must be replaced with authentic photographs. See [docs/GO-LIVE.md](docs/GO-LIVE.md).

## What is real and what is simulated

| Area | In this codebase |
|---|---|
| Registration, login, sessions, password reset, e-mail change, MFA (TOTP), account deletion | **Real.** Argon2id hashes, hashed single-use tokens, httpOnly session cookies and rate limiting. |
| E-mail | **Real** SMTP transport. In development, mails go to a database outbox that you can read at `/<locale>/dev/mailbox`. |
| Age verification | **Real** server-side enforcement, plus a provider interface with a **Veriff adapter (unverified)**. In development a labelled simulator calls the real signed webhook endpoint. |
| Messaging | **Real.** Messages are stored in PostgreSQL and pushed live over SSE using PostgreSQL LISTEN/NOTIFY. Delivered and read receipts, image attachments (re-encoded, EXIF stripped) and notifications all work. |
| Requests, offers, gift box | **Real.** A request is posted into the conversation. Accepting an offer adds it to the cart and never charges the customer. |
| Cart, checkout, discounts | **Real.** Guest and account carts are supported. Pricing and VAT are recomputed on the server. The welcome discount applies once per identity. Codes have limits and redemptions are recorded once. |
| Payments | Provider interface with a **Verotel FlexPay adapter (unverified)**. Fulfilment is idempotent and checks amount and currency. Refunds and chargebacks revoke access. In development a labelled simulator posts signed webhooks. |
| Delivery | **Real.** Files sit in private storage (local or S3). Downloads use short-lived, user-bound signed links, and entitlement is re-checked on every download. |
| Content | **Real** admin editing of products, collections, media, texts (per language), releases, look polls, discounts and settings. |
| Imagery | **Demo artwork** generated by `npm run assets:demo` and marked with a visible label. |

## Quick start (development)

Requirements: Node 22+ and PostgreSQL 16.

1. Create the database user and database:

```bash
createuser maison --pwprompt
```

```bash
createdb -O maison maison_lisa
```

2. Copy the environment template, then set `SESSION_SECRET`, `APP_ENCRYPTION_KEY` and `SEED_ADMIN_PASSWORD` (see the comments in the file):

```bash
cp .env.example .env
```

3. Install dependencies, apply migrations and seed the data. Seeding creates the admin account and the welcome discount, plus the demo catalogue when `SEED_DEMO_CONTENT=true`.

```bash
npm install
```

```bash
npm run db:migrate
```

```bash
npm run db:seed
```

4. Render the demo artwork. This step needs the Playwright Chromium browser.

```bash
npm run assets:demo
```

5. Start the development server:

```bash
npm run dev
```

The site runs at http://localhost:3000 and redirects to `/de` (the default language). Sign in as `SEED_ADMIN_EMAIL` to reach the Atelier at `/admin`. The admin area answers 404 to everyone else.

A labelled banner shows when development simulators are active. In development:
- E-mails appear at `/en/dev/mailbox`.
- Age verification opens `/en/dev/verification`, where you choose "adult" or "minor".
- Payments open `/en/dev/payment`, where you choose success or failure.

## Online preview

`render.yaml` deploys a **password-protected preview** to Render: the production build with the labelled simulators (`PREVIEW_MODE=true`), files stored in PostgreSQL (`STORAGE_DRIVER=db`), and migrations plus the demo seed on start (`npm run start:preview`). It is for testing only, never for real customers. Step-by-step guide (German): [docs/VORSCHAU.md](docs/VORSCHAU.md).

## Scripts

| Script | Purpose |
|---|---|
| `npm run dev` / `build` / `start` | Next.js development server, production build and production server |
| `npm run typecheck` | Strict TypeScript check |
| `npm test` | Unit tests (Vitest): pricing and discount allocation, verification age logic, nail-tint maths |
| `npm run test:e2e` | End-to-end Scenarios A–E plus localisation, permission, webhook and mobile checks (Playwright) |
| `npm run i18n:check` | Checks that all 8 languages have every key, with matching ICU placeholders and plurals |
| `npm run verify:all` | Runs typecheck, i18n check and unit tests |
| `npm run db:migrate` / `db:seed` / `db:reset` | Database migrations and seed (`db:reset` drops everything) |
| `npm run assets:demo` | Regenerates the demo artwork into `assets/demo` and `public/demo` |

### End-to-end tests

The tests need the database migrated and seeded with demo content, and `ALLOW_DEV_SIMULATORS=true`. If nothing is running on port 3000, Playwright starts `next dev` itself with rate limiting disabled. If you reuse your own dev server, start it with `RATE_LIMIT_DISABLED=true`. Each run creates new test customers (`*@example.test`).

```bash
npm run test:e2e
```

| Scenario | Spec |
|---|---|
| A. First-time customer: guest cart, register at checkout, verify, welcome discount, one payment, protected download | `tests/e2e/scenario-a-first-purchase.spec.ts` |
| B. Customer contacts Lisa: realtime reply, notification, read receipt, history, conversation authorisation | `tests/e2e/scenario-b-message-lisa.spec.ts` |
| C. Nail Studio and Look Studio, request, offer, accept, add a collection, pay both, production, upload, delivery | `tests/e2e/scenario-c-personal-request.spec.ts` |
| D. Discount code: refusals, validation, cart and checkout totals, single redemption, per-customer limit | `tests/e2e/scenario-d-discount-code.spec.ts` |
| E. Returning customer: language restored on the same and on a new device, verification, chats, purchases, saved cart | `tests/e2e/scenario-e-returning-customer.spec.ts` |

## Branding

The brand name, creator name and monogram are configured in one place, [`src/config/brand.ts`](src/config/brand.ts). You can override them with `NEXT_PUBLIC_BRAND_NAME`, `NEXT_PUBLIC_CREATOR_NAME` and `NEXT_PUBLIC_BRAND_MONOGRAM`. The colour and type tokens are in [`src/app/globals.css`](src/app/globals.css).
